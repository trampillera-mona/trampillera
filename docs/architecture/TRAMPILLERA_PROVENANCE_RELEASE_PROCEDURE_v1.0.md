# TRAMPILLERA Provenance Release Procedure v1.0

**Document ID:** TMP-BPS-REL-001  
**Status:** Operational procedure / key provisioning required  
**Applies to:** WORLDS & PLAY and future TRAMPILLERA asset releases

## Security model

The release process has two separate layers:

1. **Content integrity:** SHA-256 digests and byte lengths for every registered canonical asset.
2. **Publisher authenticity:** a detached Ed25519 signature over the exact manifest bytes, verified with a public key whose fingerprint is trusted independently of the website and repository being checked.

A digest alone is not a publisher identity proof. A signature whose public key is fetched from the same untrusted location as the manifest is also not an independent trust anchor.

## Local release workflow

Run from the repository root with a supported Node.js runtime:

```sh
# 1. Generate a signing keypair once, on a trusted offline machine.
node scripts/provenance-release.mjs keygen

# 2. Generate the manifest from the registry's canonical asset files.
node scripts/provenance-release.mjs manifest

# 3. Sign the exact manifest bytes. Keep the private key offline.
node scripts/provenance-release.mjs sign private/provenance/trampillera-provenance-ed25519-private.pem

# 4. Verify signature and every registered file against the manifest.
node scripts/provenance-release.mjs verify private/provenance/trampillera-provenance-ed25519-public.pem
```

The key generator uses exclusive file creation and restrictive private-key file permissions. Keep the private key outside the repository, back it up securely, and never place it in GitHub, Render environment variables, a browser bundle, or a public artifact.

## Release publication checklist

- Review every registry entry's origin, attribution, rights status, canonical path, and version.
- Run `node scripts/verify-provenance-registry.mjs`.
- Run `node scripts/provenance-release.mjs manifest`.
- Sign the manifest on the trusted offline signing machine.
- Run the local signature and content verification command.
- Publish the manifest and detached signature with the same release.
- Publish the public key and its SHA-256 fingerprint through an independently trusted channel; record the approved fingerprint in the verifier's trust configuration before claiming authenticated publisher identity.
- Test the public verifier against both an unchanged asset and a deliberately modified test copy.
- Preserve the release manifest, signature, public-key fingerprint, source commit, and release date as an audit record.

## Current implementation boundary

- `scripts/provenance-release.mjs` implements local key generation, SHA-256 manifest generation, Ed25519 detached signing, and local verification.
- `/worlds-play/verify/?id=...` fetches the manifest and canonical file and checks SHA-256 plus byte length in the browser.
- The browser verifier currently performs **hash integrity checking only**. It does not yet pin and validate the Ed25519 public key. Do not describe the public web check as cryptographically authenticated publisher verification until that trust-anchor step is implemented and independently reviewed.
- The release manifest and detached signature must be generated as part of an actual release; they are not generated by the static validation command.
- No private signing key is stored in this repository.
- No anti-copying, DRM, legal ownership determination, or trademark registration is provided by this mechanism.

## Key compromise and rotation

If a private key is suspected compromised, stop signing releases with it, publish a revocation notice through the independent trust channel, generate a new Ed25519 keypair, verify the new public-key fingerprint out of band, and document the effective release boundary. Preserve old public keys for historical signature verification; do not silently replace trust keys.
