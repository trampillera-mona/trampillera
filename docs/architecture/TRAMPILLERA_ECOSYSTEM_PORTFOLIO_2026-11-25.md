# TRAMPILLERA — Independent Technology & Research Portfolio

**Snapshot date:** 2026-11-25  
**Repository:** `trampillera-mona/trampillera`  
**Purpose:** Preserve the wider project portfolio and distinguish deployed software, working prototypes, research initiatives, and concepts.  
**Important boundary:** This portfolio document records project context. It does not imply that every listed initiative is a module of the TRAMPILLERA application, that every project is deployed, or that conceptual capabilities have been implemented.

## 1. Portfolio position

TRAMPILLERA is an independent technology and research ecosystem developed incrementally with limited resources. Its working method is to publish experiments, preserve authorship and development history, test useful ideas, and describe implementation status honestly. It does not claim to be a university, a global AGI foundation, a large corporation, or an established international institute.

**Working principle:** Build useful things, expose evidence, preserve unknowns, and collaborate only under clear terms.

**Evidence rule:** A displayed capability is not a verified capability. A declared status is not an execution result.

## 2. Primary technology platform

### TRAMPILLERA MEDIA
- Public entry: https://trampillera.com/
- Repository: https://github.com/trampillera-mona/trampillera
- Deployment target: Render web service `trampillera`; Docker application rooted at `app/`; PostgreSQL dependency.
- Product position: Independent Network of Connected Perspectives; experimental multimodal media and technology platform.
- Current implementation is a modular monolith in deployment, with a federated logical architecture target. These are not contradictory: modules can retain independent ownership and contracts while initially sharing one deployable Node.js service.

### JARVISER
- Purpose: AI assistant and future agent-orchestration environment.
- Current implementation: server-side single-turn AI chat endpoint with Qwen Model Studio as the default adapter and OpenAI as an explicitly selected alternative.
- Triage / Analysis / Synthesis are workflow concepts and UI vocabulary. A durable multi-agent runtime, queue, tool-permission engine, persistent conversations, and independently verified workflow execution are not yet established.
- The provider catalogue is not proof that every listed model is configured or reachable.

### Control Plane and operational modules
- Authenticated administrator Control Plane and PostgreSQL-backed registries exist.
- Module lifecycle transitions require explicit allowed targets and operator notes, with transactional audit recording.
- Team Game is server-backed with employee sessions, missions, submissions, discussion polling, administrator review, and verified XP.
- Workspace, Campus, and Multiverse remain predominantly browser-local prototypes and must not be described as synchronized server-backed environments.
- Audience Intelligence & Growth includes opt-in pseudonymous visitor measurement, aggregate analytics, campaign management, and tracked redirects with UTM attribution.
- Comms and Scene Studio are prototypes, not verified persistent messaging/E2EE or server-persisted scene services.

### Language and voice
- Twelve locale options are declared: EN, RU, SR, DE, FR, ES, IT, PT, ZH, JA, KO, AR.
- Shared language controls and voice-command vocabulary have automated source tests.
- Browser speech recognition and speech synthesis depend on browser/OS capabilities and user permission.
- Full translation of every screen and every string is not complete; locale presence in the selector is not proof of complete translation or speech recognition on every device.

## 6. Project boundary and ownership discipline

1. The TRAMPILLERA repository is the source of truth for the TRAMPILLERA application code and its technical documentation.
2. Separate Vercel prototypes remain separate deployments unless an explicit integration is implemented and tested.
3. A shared visual identity or conceptual relationship does not establish shared runtime, shared database, or common ownership of data.
4. Every project page must distinguish LIVE / IMPLEMENTED, PARTIAL, PROTOTYPE, CONCEPT, and UNKNOWN states.
5. Never publish secrets, private keys, personal credentials, or sensitive partner data in this repository.
6. Preserve project attribution, commit history, source snapshots, and dated architecture decisions.
7. Partnership, licensing, access to source code, and transfer of intellectual property require explicit, separately documented approval.

## 7. Portfolio priorities

1. Stabilize and verify TRAMPILLERA as the primary deployed platform.
2. Keep JARVISER provider execution claims evidence-scoped; build durable orchestration only through explicit contracts and tests.
3. Complete language coverage and real-device voice testing before claiming full multilingual support.
4. Preserve the distinction between server-backed Team Game and browser-local ITY CITY prototypes.
5. Build SDT5D+/ArtMer demonstrations around real, attributable territorial data.
6. Develop Le Bureau as a transparent research initiative with named research questions, methods, source data, and reproducible outputs.
7. Avoid multiplying new product labels until existing projects have useful, verifiable deliverables.
