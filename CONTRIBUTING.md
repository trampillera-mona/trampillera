# Contributing to TRAMPILLERA

Thank you for your interest in improving TRAMPILLERA. The project welcomes practical, respectful contributions that make the platform more useful, secure, understandable, and maintainable.

## Before you contribute

1. Read the [README](./README.md), [MIT License](./LICENSE), [licensing notes](./LICENSING.md), and [brand-use rules](./TRADEMARKS.md).
2. Check existing issues and pull requests to avoid duplicate work.
3. For substantial changes, open an issue or discussion first and describe the problem, proposed approach, and affected areas.
4. Never include passwords, API keys, private tokens, personal data, production database dumps, or other secrets in issues, commits, screenshots, or test fixtures.

## Ways to contribute

- Report reproducible bugs and security concerns.
- Improve documentation and setup instructions.
- Submit focused fixes, tests, accessibility improvements, and performance work.
- Propose integrations or modules with clear boundaries and documented dependencies.

## Pull request expectations

- Keep each pull request focused and explain the user-visible effect.
- Describe the problem, the solution, and any trade-offs.
- Include reproduction or test steps. Update tests and documentation when relevant.
- Preserve existing behavior unless the change intentionally modifies it.
- Do not commit generated secrets, local environment files, database contents, build artifacts, or unrelated formatting churn.
- Identify third-party code, assets, and dependencies you introduce, including their licenses.
- Be clear about what has actually been tested. Do not describe an unverified feature as working or production-ready.

Maintainers may request changes, ask for clarification, or decline contributions that are out of scope, unsafe, legally unclear, or inconsistent with the project's direction.

Contributors are welcome to acknowledge their work in commit history, pull requests, release notes, or documentation. Do not remove existing copyright or license notices.

## Forks and independent deployments

Forks and independent deployments are welcome under the MIT License. Please:

- retain the required copyright and license notices;
- state that your version is a fork or independent derivative and identify material changes;
- choose a distinct project name, domain, logo, and visual identity;
- do not suggest that your fork is official, endorsed, operated, certified, or supported by TRAMPILLERA;
- follow [TRADEMARKS.md](./TRADEMARKS.md) when referring to the project name or marks.

A fork may be developed and distributed commercially, subject to the MIT License, third-party licenses, applicable law, and the separate brand-use rules. The MIT License does not create an exclusive commercial territory or prevent others from building competing products.

## Community standard

Be constructive, specific, and respectful. Critique ideas and implementation, not people. See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md).

Thank you for helping build an open, independent, and responsible ecosystem.
